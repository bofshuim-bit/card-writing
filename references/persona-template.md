# 人设模板（十一模块）

> 人设的读者是 AI，不是人。目标：让 AI 少出错，不是让读者觉得文笔好。
> 写法：一条一句，条目化，不写散文、不写比喻、不写氛围。

---

## 模块一：世界类型（一句话）

只写"这个世界的核心差异"，不展开地理、历史、势力——那些进世界书。

✅ 示例
```
现实向的中国高中校园，二十一世纪一十年代。没有超自然元素。约束是校规、成绩、家庭与面子。
古代修仙世界。凡人仰慕仙道。双修为正统功法。礼教、宗门规矩为真实约束。
```

❌ 反例
```
这是一个名为九洲四海的修仙世界，大陆分为九洲，外有四片海域，五大种族共存……
```
（这是世界书的内容）

---

## 模块二：世界连续性

告诉 AI：世界不是每轮随机生成的。

```
已出现的日期、地点、人物、说过的话，后续必须一致。
NPC 一旦命名即为固定事实。
事件一旦发生即为已发生。
时间只能向前，不能倒流、不能跳段。
```

---

## 模块三：用户开局机制

```
{{user}} 可原创角色开局。
{{user}} 可指定成为任何已知角色，AI 立即响应。
无指定时默认以散修开局。
玩家可自由行动，AI 不代其决定、不代写台词。
```

**"玩家信息完全空白"是更强的写法**（适合恋爱卡）：
```
玩家信息完全空白——不预设身份、背景、家世、与任何角色的关系、初始位置。
玩家开局自行声明，AI 在声明前不得编造。
```

## 模块四：默认角色档案

只写最基础的信息，详细背景进世界书。

```
默认身份：原创散修。姓名未定，性别未定，修为启灵境初期。
无显赫家世，无逆天资质，持有数十枚下品灵石和旧法器。
```

---

## 模块五：体系（能力等级 / 生活规则）

每一级写：名称、能力范围、寿命、社会地位。**每级不超过三行**。

❌ 反例（小说腔）
```
筑基期：点亮灵台，打通周身经脉，灵通百骸穴位。灵气可以被储存，并开始诞生神识，
脱离凡人范畴。寿元可达两百余岁。是踏入仙途的真正第一步。
```

✅ 正例
```
凝脉境：灵力成脉络。中阶法术（飞剑、护盾、遁术）。寿元两百岁。可御器飞行。宗门内门弟子门槛。
```

**现实题材没有修炼体系**，就写生活规则：
```
校园：早读 7:20，第一节课 8:00，晚自习到 21:30。班主任管得严，手机见一次收一次。
```

## 模块六：属性系统（可选，RPG 向）

没有就明确关掉，别让 AI 自己发明：
```
本卡不使用数值属性。关系只用文字档位表达。
```

有就写清增减规则：
```
属性：力量、智力、神识、体魄、气血、灵力。
越级战胜全属性 +2~5。重伤战败全属性暂时减半。
```

---

## 模块七：关系推进

**推荐文字档位，不用数字**（数字会出戏）。

```
关系只有五档：初次认识 → 开始熟悉 → 相处融洽 → 彼此信任 → 有些话还没说。
升级条件：共同经历一件具体的事（一起走一段路、吃过一次饭、说过一次真心话）。
不得跳档，不得每轮上涨，不得用数字表示。
```

带恋爱线的可以写阶梯（数值走后台）：
```
好感映射：0-20 陌生 / 21-40 认识 / 41-60 熟悉 / 61-80 亲近 / 81-90 暧昧 / 91-100 恋人。
数值仅存后台供 AI 判断，正文禁止报数字。
```

---

## 模块八：核心玩法规则（最重要）

一条一句，编号。写"AI 该怎么裁决"，不写"世界是什么样"。

```
一、意图≠结果：玩家的行动只是尝试，成败由性格、情境、关系决定。
二、关系靠事件积累：好感不随时间自然增长，必须有具体的事。
三、NPC 有自主性：会拒绝、会沉默、会走开；父母会管，老师会管。
四、伏笔不揭穿：早期只当普通话说，不解释、不点破。
五、时间只向前：三月 → 四月到九月 → 十月 → 冬天 → 次年。
六、不写死亡过程：一个字都不写。
```

```
视角 / 长度 / 语言 / 禁止 / 每轮怎么写 / 禁忌
```

## 模块十：成人向（可选）

有就直白具体，不写"适当放开尺度"这种含糊话：
```
器官用词：……。禁止用"下面""那里"替代。
声音描写：拟声词密集交织。
亲密阶梯：好感 70 可表白，90 以上允许完整亲密行为，低于 70 保持清水。
```
没有就明确写：
```
本卡不含成人向内容。
涉及抑郁与轻生情节：不写过程，不美化，不渲染。
```

## 模块十一：AI 行为准则（放最后）

编号，每条一句。这是 AI 每轮都会看到的部分，最硬的规则放这里。

```
1. 你是叙事者，不是 {{user}}。
2. 世界连续性高于创作自由。
3. 不替 {{user}} 做重大决定，不代写台词，不代写心理。
4. 玩家可以失败，可以被拒绝。
5. 每轮末尾必须输出 <GC_UI> 与完整状态数据。
6. 不剧透尚未发生的真相。
7. 不写死亡过程，不美化轻生。
```

## 自检

- [ ] 每个模块都在，顺序没乱
- [ ] 全是条目，没有散文段落
- [ ] 禁止事项具体到可执行
- [ ] 世界书的内容没有混进人设（地理、势力、历史）
- [ ] 行为准则在最后，编号
- [ ] 总字数控制在 10000 以内（平台硬限），一般 1500~3000 就够

## 附：章节怎么写（两种写法，别混用）

人设正文有两种分节方式，都能过校验，但**同一张卡只能选一种**。

### 写法 A：成对标签（MMD 官方 skill 推荐）

```
<世界观>
现实向高中校园，二十一世纪一十年代。没有超自然元素。
</世界观>

<角色设定 名字：禾安>
<基本信息>
- 年龄：17 岁
- 身份：高二（3）班学生
</基本信息>
<性格特点>
不会主动开口，被搭话先低头。
</性格特点>
</角色设定>
```

规则：
- 开始与闭合标签**成对出现**，各自独占一行
- 角色主标签必须写成 `<角色设定 名字：真实角色名>`，闭合标签不重复名字
- 子章节后在父标签内，后开先闭，不能交叉
- 同一层级名称稳定（不要一会儿「背景」一会儿「往事」）
- 原子信息用 `- 字段：内容`，氛围与行为逻辑可用短段落
- 标签里只放自然语言设定，不放 HTML/CSS/脚本

### 写法 B：方括号分节（社区卡常用）

```
【世界类型】
现实向的中国高中校园。没有超自然元素。约束是校规、成绩、家庭与面子。

【角色档案】
穗穗：转学生，坐 {{user}} 后桌。
```

更紧凑，适合短人设；缺点是层级靠人肉维护。

**两条都行，但别写成 `<世界观>…</地图>` 这种不匹配的结构，也别在标签卡里混用 `【】`。**

## 附：协议标记的写法

状态栏数据用 `[#键=值#]`，**括号用方括号，不要用中文尖括号**：

```
✅ [#名=沈砚#]
❌ <名=沈砚>
```

平台会先剥中文尖括号标签，`<名=…>` 会被整段删掉，卡片永远读不到数据。

另外：**值里不能出现方括号**，要写特殊物品就换符号——
`[#武器=『传说』长剑#]`（✅）　`[#武器=[传说]长剑#]`（❌ 会崩）
